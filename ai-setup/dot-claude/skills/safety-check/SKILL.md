# /safety-check — перевірка перед комітом

1. Збери зміни: `git diff --stat` і `git diff` (якщо git ще не ініціалізований — список змінених файлів за задачею).
2. Автоматичні перевірки (з `apps/backend`):
   ```bash
   uv run ruff check . && uv run ruff format --check .
   uv run mypy app
   uv run pytest -q -m "not testnet"
   ```
   Для фронтенду (якщо змінений): `npm run typecheck && npm test`.
   Також: `python3 scripts/sync_ai_rules.py --check`.
3. Визнач клас ризику змін (за `docs/ai/TASKS.md`): R3 якщо зачеплено `exchange/ trading/ risk/ protection/ reconcile/`, Emergency Stop, робота з ключами біржі.
4. Незалежне рев'ю:
   - у Claude Code — делегуй субагенту `trading-safety-reviewer` (для `ml/` — ще й `ml-leakage-auditor`), передай лише список файлів/дифф, **без** своїх пояснень, щоб рев'ю було незалежним;
   - у Cursor — пройди чекліст нижче сам, у новому чаті, бажано іншою моделлю.
5. Чекліст (кожен пункт — так/ні/н.з. з посиланням на рядок):
   - [ ] Немає шляху збільшення експозиції поза `RiskGate`.
   - [ ] Невизначеність → блок нових входів, але не захисту/закриття.
   - [ ] Write-ahead перед мережевим викликом; таймаут → `SUBMISSION_UNKNOWN`.
   - [ ] Ідемпотентність підкріплена UNIQUE в БД.
   - [ ] `Decimal` для грошей, `int` мс для часу, округлення вниз до `qtyStep`.
   - [ ] Немає look-ahead (для ML).
   - [ ] Секрети не логуються; немає mainnet у тестах.
   - [ ] Тести покривають збої, а не лише щасливий шлях; жоден тест не послаблено/вимкнено.
   - [ ] Значення ризиків за замовчуванням не стали ризикованішими.
   - [ ] Документація відповідає коду: для кожної зміненої поведінки/параметра/статусу/таблиці/API/команди знайдено (`grep`) і оновлено всі описи в `AppInfo.md`, README модулів, `docs/**`, `.env.example`, довідці UI; розбіжності з ТЗ погоджені з користувачем і записані в `docs/decisions/`.
6. Підсумок: `ПРОЙДЕНО` / `БЛОКЕРИ: …` / `ЗАУВАЖЕННЯ: …`. З блокерами коміт не робиться.
