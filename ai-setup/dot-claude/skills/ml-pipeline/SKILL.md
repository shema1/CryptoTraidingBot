# ML-пайплайн без витоку даних

Вимоги: ТЗ §5, §5А. Детальні правила — `.claude/rules/ml-pipeline.md`.

## Перед зміною фіч
1. Кожна нова фіча: формула, вікно, з яких свічок рахується. Переконайся, що використовується лише `<= t-1`.
2. Заборонені конструкції: `shift(-n)`, `center=True`, `bfill`, `fillna(method="bfill")`, глобальні `mean/std` по всьому датасету, `fit` скейлера до розбивки, `resample` з `label="right"` без перевірки, `merge_asof` без `direction="backward"`, funding rate з майбутнього таймстемпу.
3. Оновлюється `feature_schema_hash` (автоматично зі списку фіч і параметрів) і `preprocessing_version` (вручну, semver).

## Обов'язкові тести (додай/онови)
- **Look-ahead:** змінити дані після `t-1` (випадковим шумом) → фічі для `t` не змінились.
- **Parity:** інкрементальний розрахунок по кільцевому буферу == офлайн-розрахунок на всій історії (для останніх N рядків, допуск `1e-9`).
- **Shuffled labels:** на перемішаних мітках net PF ≈ 1 / результат ≈ 0.
- **Таргет:** синтетичні свічки, де TP і SL в одній свічці → клас SL; slippage зсуває вхід проти угоди.
- **Gaps:** вікно, що перетинає `data_gaps`, виключене.
- **Розбивка:** між train і test є embargo ≥ `horizon_bars`; індекси hold-out не потрапляють у жоден фолд/Optuna.

## Бектест
- Модель виконання = live: вхід по `open[t]`, комісія taker/maker, slippage (фікс + частка ATR), funding, затримка входу; розмір — через `risk.sizing.calc_position_size()`.
- Перевірка стійкості: подвоєння комісії та slippage.

## Інтерпретація
Якщо результат «занадто хороший» (PF/Sharpe > 3, accuracy > 80%) — спочатку шукай витік, повідом користувача, не позначай модель як успішну.
Після зміни — субагент `ml-leakage-auditor`.
