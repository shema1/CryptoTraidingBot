# /next-task — взяти задачу з плану

1. Прочитай `docs/ai/TASKS.md`. Якщо передано ID (наприклад `T3.3`) — візьми її; інакше — першу задачу зі статусом `[ ]`, у якої всі залежності `[x]`.
2. Покажи користувачу: ID, назву, клас ризику, **рекомендовану модель і effort**, режим (Plan/звичайний), залежності.
3. Якщо поточна модель сесії слабша за рекомендовану (порядок: fable > opus > sonnet > haiku) — попередь і запропонуй `/model <alias>` та `/effort <level>`; не починай R3-задачу на sonnet/haiku без явної згоди.
4. Прочитай розділи ТЗ, вказані в задачі, і релевантні rules/skills.
5. Склади план: файли, тести (спочатку), кроки, **документи, які треба оновити** (ТЗ, README модуля, docs/**, `.env.example`, довідка UI), ризики, що перевірити на Testnet. Якщо під час аналізу видно розбіжність коду з ТЗ — винеси її окремим питанням до користувача. Для R3/R2 — дочекайся підтвердження плану.
6. Після підтвердження — постав статус `[~]` (в роботі) у TASKS.md і виконуй.
7. Після виконання: тести, оновлення документації (правило `.claude/rules/documentation.md`), `/safety-check` для R2/R3, статус `[x]`, коротка нотатка в «Примітках» задачі. Підсумок містить розділ «Документація»: що оновлено або чому не потрібно.
