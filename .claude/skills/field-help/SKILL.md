# Підказки FieldHelp (ТЗ §16А)

1. Кожен елемент UI з ТЗ §16А.3 має `<FieldHelp id="<ключ>" />`. Ключ = назва поля з OpenAPI (`risk.risk_per_trade_pct`, `status.SUBMISSION_UNKNOWN`, …).
2. Текст додається лише у файл довідки `apps/web/src/help/help.uk.json` (або `.ts`) зі структурою:
   ```json
   "risk.risk_per_trade_pct": {
     "short": "Максимальний збиток в одній угоді у % від капіталу.",
     "long": "Яку частину капіталу ви готові втратити в одній угоді, якщо спрацює стоп-лосс.",
     "example": "Капітал 1000 USDT, значення 0,5% → максимальний збиток 5 USDT.",
     "default": "from-openapi",
     "range": "from-openapi",
     "warning": "Значення вище 2% небезпечне."
   }
   ```
3. Popover (складні/небезпечні параметри) — 5 частин: що це; приклад з числами; default і діапазон; що буде при збільшенні/зменшенні; попередження (для ризикових).
4. Default/range не вписуються вручну — підтягуються з OpenAPI-схеми.
5. Мова — проста українська, без жаргону; терміни англійською лише як у ТЗ (з поясненням).
6. **Фактична точність важливіша за стиль**: опис параметра ризику має точно відповідати тому, як бекенд його використовує. Якщо не впевнений — прочитай код Risk Engine, а не вигадуй.
7. Онови/перевір тест, що всі поля конфігурації бекенду мають запис у довідці: `npm test -- help-coverage`.
