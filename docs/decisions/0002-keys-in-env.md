# 0002. Ключі біржі в `.env` замість шифрованого сховища в БД

- **Дата:** 2026-10-28
- **Статус:** прийнято (підтверджено власником проєкту)
- **Зачеплені розділи ТЗ:** §0 (ризики), §3, §13, §14, §15 (`exchange_accounts`), §16 (група `/keys` прибрана), §16А.3, §17
- **Зачеплені задачі:** T0.5 видалено; T3.6 переписано

## Контекст

ТЗ v3.0 передбачало зберігання API-ключів у БД із шифруванням AES-256-GCM ключем із `.env` і введення ключів через UI (`/keys`). Проєкт особистий, працює на одному ПК. Ключ шифрування лежав би в тому ж `.env` на тому ж диску, що й БД, тож будь-хто з доступом до диска мав би й ключі. Реальний захист така схема майже не додає, а коштує задачу класу R3.

## Рішення

| Було | Стало |
|---|---|
| Ключі в БД, AES-256-GCM, `ENCRYPTION_KEY` у `.env` | Ключі лише в `.env` (`BYBIT_TESTNET_API_KEY/SECRET`, `BYBIT_DEMO_API_KEY/SECRET` — див. 0003, `BYBIT_LIVE_API_KEY/SECRET`), `chmod 600`, не в git |
| Введення і зміна ключів через UI / API `/keys` | Зміна ключа — правка `.env` і перезапуск; в UI лише статус перевірки дозволів |
| Перевірка дозволів при збереженні ключа | Перевірка дозволів при кожному старті; ключ із правом виводу → боти цього режиму не стартують |
| `exchange_accounts` містить зашифровані ключі | `exchange_accounts` містить лише режим, посилання на набір змінних і результат перевірки |

Без змін лишається основний захист: ключ без права виводу, IP whitelist, окремий субакаунт з обмеженим балансом, `SecretStr` і маскування секретів у логах, заборона агентам читати `.env` (hooks).

## Наслідки

- Задача T0.5 (R3, Fable) видалена; T3.6 охоплює читання ключів з `.env` і перевірку дозволів при старті.
- Немає коду шифрування, таблиці ключів, API `/keys` і форми в UI.
- `.env` треба зберігати в резервній копії окремо від дампів БД (менеджер паролів або інше зашифроване сховище).
- Розглянуті й **не прийняті** спрощення (лишаються як у ТЗ): простіший rate limiter, простіший advisory lock, спрощення годинника і сповіщень, простіші бекапи, ML через CLI замість ML Studio, зміна моделі лише на зупиненому боті, легший захист локального API, audit_log у файл.
